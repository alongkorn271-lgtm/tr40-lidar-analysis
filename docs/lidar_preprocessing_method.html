TR40 LiDAR Data Pre-processing

Full-pipeline method and the theory behind each step — raw .dat to Normalized Relative Backscatter (NRB), depolarization, and the Klett–Fernald aerosol retrieval

NARIT — Princess Sirindhorn AstroPark, Chiang Mai  ·  532 nm elastic (Mie) LiDAR  ·  biaxial Celestron EdgeHD + Licel TR40 (analog mV + photon MHz), 2 polarization channels (∥/⊥)

What this document covers. The core signal pre-processing chain: how one raw .dat acquisition becomes a calibrated backscatter profile, and the depolarization ratio built from the ∥/⊥ channels. Each step below states the physics problem, the equation(s) as implemented in the code, and why it must run in that order.

Part B then documents the on-demand retrieval that runs after this chain — the Rayleigh molecular model, the analytical overlap function \(O(R)\), the Klett–Fernald inversion (aerosol backscatter/extinction/AOD), and PBL/ALT layer detection. The MPL and AERONET readers are validation inputs and are only pointed to where relevant.

Processing order & the NRB equation

The pipeline targets one master equation (the SigmaMPL form of the lidar backscatter product), built up correction-by-correction inside compute_nrb_reference_glue() (an optional final \(\div\max\) gives the unit-max profile of Step 10):

$$\mathrm{NRB}(R)\;=\;\frac{\big[(\text{Raw}\cdot\text{DT}) - \text{Afterpulse} - \text{BG}\big]} {\text{Overlap}(R)\cdot E}\;\cdot\;R^{2}\tag{0}$$

Every term in Eq. (0) is a term of the general single-channel elastic-lidar equation, so each step below "undoes" one physical effect:

$$P(R)\;=\;P_0\,\frac{c\tau}{2}\,\frac{A}{R^{2}}\,O(R)\,\beta(R)\, \exp\!\Big[-2\!\int_0^{R}\!\alpha(R')\,dR'\Big]\tag{L}$$

DT corrects detector pile-up; BG removes the solar/electronic pedestal; Afterpulse removes a detector ghost; dividing by Overlap \(O(R)\) fixes the biaxial near field; \(\times R^2\) undoes the \(A/R^2\) geometric fall-off; \(\div E\) normalizes by laser pulse energy. The molecular/aerosol backscatter \(\beta(R)\) and transmission \(\exp[-2\!\int\alpha]\) are recovered later by the inversion (out of scope).

The steps run in the following dependency order (this is the order of the document):

  1. Raw .dat ingest — parse the 4-column TR40 ASCII, drop pre-trigger bins, map bin → range.
  2. Dead-time correction of the photon channel (run first, because the background is measured on the corrected rate).
  3. Background estimation (pre-trigger / fixed / far-range gate).
  4. Day/night toggle-rate window — choose the photon-rate band used to select the glue region.
  5. Analog↔photon glue — cross-calibrate the two detectors and blend them.
  6. Background subtraction.
  7. Afterpulse correction (optional).
  8. Overlap correction \(O(R)\) (optional).
  9. Range² + energy normalization → NRB.
  10. Max normalization (0–1 profile).
  11. SNR of the photon channel.
  12. SNR gating / trusted-range normalization (optional).

All of the above is implemented in nrb_engine.py; the per-file orchestrator is build_single_profile() and the per-day batch is build_daily_profile_from_folder(). Depolarization is in depol_engine.py.

1Raw .dat ingest & bin → range mapping

The physics problem. The TR40 writes an ASCII file with four columns per range bin: analog signal (mV), analog standard error, photon-counting rate (MHz), and photon standard error. The first block of bins is pre-trigger (recorded before the laser fires) and carries no atmospheric return — only baseline. Each remaining bin corresponds to a fixed round-trip time, so it maps to a geometric range.

Range is a uniform grid anchored at the first true signal bin, and the time-per-bin follows from the range spacing (round-trip, hence the factor 2 and speed of light \(c\)):

$$R_i \;=\; R_0 + i\cdot \Delta R,\qquad i=0,1,\dots\tag{1a}$$ $$\Delta t_{\text{bin}} \;=\; \frac{2\,\Delta R}{c}\times 10^{9}\ \text{ns},\qquad c=299\,792\,458\ \text{m/s}\tag{1b}$$

With \(\Delta R = 3.75\) m this gives the expected 25 ns bin (the code snaps to exactly 25.0 ns when within 0.25 ns).

range_m       = first_signal_range_m + np.arange(n) * dr_m          # (1a)
bin_width_ns  = (2.0 * dr_m / 299792458.0) * 1e9                    # (1b)

nrb_engine.py · read_tr40_dat_ascii(), bin_width_ns_from_dr(), trim_pretrigger_tail(). Config: dr_m=3.75, pretrigger_bins=1024, first_signal_range_m=3.75, start_mode="auto".

2Dead-time (pile-up) correction of the photon channel

The physics problem. A photon-counting detector counts pulses one at a time; after each count there is a short "dead time" \(\tau_d\) during which the next photon is missed. The higher the true rate \(S\), the more counts are lost — so the measured rate \(N\) always under-reads.

The code uses the non-paralyzable model (the standard choice for a PMT + discriminator that resets cleanly after \(\tau_d\)):

$$N \;=\; \frac{S}{1 + S\,\tau_d}\qquad\Longrightarrow\qquad S \;=\; \frac{N}{1 - N\,\tau_d}\tag{2}$$

with \(N,S\) in MHz and \(\tau_d\) in ns (the factor \(10^{-3}\) in the code converts MHz × ns). The correction is only valid while \(N\tau_d < 1\); as \(N\tau_d\to1\) the denominator collapses, so the code returns NaN instead of a blow-up. For \(\tau_d = 3.06\) ns the model breaks near \(1/\tau_d \approx 326\) MHz — a hard ceiling that reappears in Step 4.

Why this must run before Steps 3–5. The raw photon rate is a non-linear function of the true signal (Eq. 2), so it cannot be regressed against the linear analog channel. Dead-time correction makes the photon channel linear again first; only then are the background (Step 3, measured on the corrected rate) and the analog↔photon fit (Step 5) meaningful.
denom = 1.0 - rate_mhz * dead_time_ns * 1e-3        # (2), 1 - N·τ_d
photon_dt_mhz = rate_mhz / where(|denom|<1e-12, nan, denom)

nrb_engine.py · dead_time_correct_mhz(). Config: dead_time_ns=3.06.

3Background estimation

The physics problem. On top of the atmospheric return sits a constant pedestal: daytime solar sky radiance plus electronic offset. It must be measured so it can be removed (Step 6). Three gates are supported.
ModeGateEstimate
pretrigger (default)the pre-trigger bins (before laser fire)mean of the dead-time-corrected rate over those bins
fixeda user range window [bg_start_m, bg_end_m]mean over that window
far_rangethe far tail, \(0.88\,R_\max \le R \le 0.98\,R_\max\)mean over that window
$$\text{BG} \;=\; \big\langle\, S_{\text{photon}}(R)\,\big\rangle_{\text{gate}}\tag{3}$$

The background is computed on the dead-time-corrected rate (hence Step 2 first), and its value is carried forward to Step 6 and to the SNR (Step 11).

4Day/night toggle-rate window

The physics problem. The glue (Step 5) fits analog against photon only where both channels are trustworthy: photon not yet saturated, analog above its noise floor. That "toggle window" is a band of photon count rate \([\,\text{min\_toggle},\ \text{max\_toggle}\,]\). Both limits come from separate physics.

Upper limit — how much dead-time correction you are willing to trust. From Eq. (2) the correction factor is \((1-N\tau_d)^{-1}\); tolerating a fraction \(\varepsilon\) of correction gives

$$\text{max\_toggle} \;\approx\; \frac{\varepsilon}{\tau_d}\;\;\Rightarrow\;\; 10\ \text{MHz}\ (\approx 3\%\ \text{correction at }\tau_d=3.06\ \text{ns}).\tag{4a}$$

Lower limit — must sit above the photon background floor and the analog 3σ noise, so the descending rate genuinely crosses it:

$$\text{min\_toggle} \;=\; \max\!\big(k\,\sigma_{\text{analog}}G,\ \sim\!2\times\text{photon floor}\big)\;\approx\;2\ \text{MHz}.\tag{4b}$$
Day vs night. Daylight lifts the whole photon profile by a large solar pedestal, so the night window can end up with zero bins inside it. The code picks the window per profile: if the pre-trigger background exceeds toggle_bg_switch_threshold_mhz it uses the day rates, otherwise the night rates. This choice is what makes the daytime glue in Step 5 possible.

nrb_engine.py · select_toggle_rates(). Config: min/max_toggle_rate=2.0/10.0 (night), day_min/max_toggle_rate, toggle_bg_switch_threshold_mhz=10.0, auto_toggle_selector=True.

5Analog↔photon glue centerpiece

The physics problem. The two channels measure the same backscatter through different detectors: analog is linear and unsaturated in the strong near field, photon counting is low-noise but saturates when strong. Over the range where both are linear, one is a straight-line rescaling of the other. "Glue" fits that line, converts analog into photon units, and blends the two into a single profile that is good at all ranges. This follows Licel §9.7.5.

5a · Regression (cross-calibration)

Least-squares fit over the toggle window from Step 4:

$$\text{photon\_dt} \;\approx\; k\cdot\text{analog} + b\tag{5a}$$ $$\text{analog\_scaled} \;=\; k\cdot\text{analog} + b\tag{5b}$$

with fit quality \(r^2 = \max\!\big(0,\,1-\tfrac{SS_{\text{res}}}{SS_{\text{tot}}}\big)\) and \(\text{RMSE}=\sqrt{SS_{\text{res}}/n}\). Here \(k\) is the gain ratio between the two detectors and \(b\) the offset.

5b · Toggle-rate cosine blend

Blend with a smooth weight \(w(R)\in[0,1]\) so there is no discontinuous seam. Let \(r_1,r_2\) be the blend-zone edges (auto-detected where the photon rate descends through the toggle limits):

$$w(R)=\begin{cases} 0, & \text{photon}(R)\ge \text{max\_toggle}\quad(\text{near: use analog})\\[4pt] 1, & \text{photon}(R)\le \text{min\_toggle}\quad(\text{far: use photon})\\[4pt] \dfrac{1-\cos\!\Big(\pi\,\dfrac{R-r_1}{r_2-r_1}\Big)}{2}, & r_1

5c · Daytime BG-subtracted glue + quality guard 2026–08

The dawn/dusk problem. Two raw profiles 30 min apart (05:44 vs 06:14) are near-identical once the background is removed, yet the old logic sent the later one to photon-only because its background (≈40 MHz) exceeded the window — giving a wrong, saturated near field. Root cause: a high solar background lifts the whole photon profile above the [2, 10] MHz toggle window, so zero bins fall inside it and the fit cannot run.

Fix (gluing_mode="auto_bgsub_guarded"). Select the fit region and blend zone on the signal above background, \(\text{photon}_{\text{toggle}}=\text{photon\_dt}-\text{BG}\), so the glue runs again when BG is high (the regression target and the glued output still use the full \(\text{photon\_dt}\); BG is removed later in Step 6). This is exactly Licel §9.7.5: "background above min toggle → use the scaled analog."

Quality guard. If the analog↔photon fit is poor — the analog channel degraded by daytime clipping or PMT protection — the glue is not trusted and the profile falls back to photon-only:

$$\text{reject glue}\ \Longleftrightarrow\ \big(r^2 < r^2_{\min}\big)\ \text{ or }\ \big(k\le 0\big), \qquad r^2_{\min}=0.85.\tag{5e}$$

Verified on real dawn data (04-21): backgrounds 13/40/123 MHz all glue with \(r^2=0.99/0.99/0.98\), and the near-field magnitude at 1 km (1790) becomes comparable to the adjacent night profile (1957) instead of a saturated photon-only value. Full midday (\(r^2\le0.54\)) is correctly rejected by the guard and left as photon-only. Night glue is unchanged and matches the lab's LabVIEW processing.

slope, offset, r2, rmse, n = linear_regression_stats(analog[fit], photon_dt[fit])  # (5a)
analog_scaled = slope * analog + offset                                            # (5b)
guard_failed  = (mode == "auto_bgsub_guarded") and not (r2 >= 0.85 and slope > 0)   # (5e)
if any(isfinite(analog_scaled)) and not guard_failed:
    w = cosine_taper_weight(r, r1, r2)          # (5c)
    w[photon_toggle > max_toggle] = 0.0         # near -> analog
    w[photon_toggle < min_toggle] = 1.0         # far  -> photon
    glued = (1 - w) * analog_scaled + w * photon_dt                                 # (5d)
else:
    glued = photon_dt.copy()                    # photon-only fallback

nrb_engine.py · compute_nrb_reference_glue(), linear_regression_stats(), cosine_taper_weight(), auto_find_blend_zone_from_threshold_crossings(). Config: gluing_mode, auto_blend=True, blend_r1_m/r2_m, day_glue_min_r2=0.85.

6Background subtraction

The physics problem. Remove the pedestal measured in Step 3 from the glued profile, so that only the true atmospheric return remains.
$$\text{glued\_bgsub}(R) \;=\; \text{merged}(R) - \text{BG}\tag{6}$$
Why after glue, not before. The blend (Step 5) is applied to every bin including pre-trigger, so the pre-trigger portion of the merged profile is itself the cleanest background reference. Subtracting a single scalar BG afterwards keeps analog and photon on the same zero level.

nrb_engine.py · master chain in compute_nrb_reference_glue().

7Afterpulse correction optional

The physics problem. Photo-electrons trapped in the PMT dynodes are released later in time, producing a range-dependent "ghost signal" — the afterpulse \(A(R)\). It is a detector-side artifact (independent of the atmosphere), so it is subtracted before any geometric correction.
$$\text{glued\_ap}(R) \;=\; \text{glued\_bgsub}(R) - A(R)\tag{7}$$

\(A(R)\) is measured separately (capped/blocked telescope) and supplied on the same range grid; if not provided, the step is skipped. On this system the afterpulse has not yet been reliably measured (low SNR), so it is usually off.

nrb_engine.py · applied when afterpulse_A_R is supplied (array from afterpulse.py).

8Overlap correction \(O(R)\) optional

The physics problem. Because the laser and the telescope have separate axes (biaxial geometry), the beam and the field of view do not fully overlap in the near field. The overlap function \(O(R)\in[0,1]\) rises from 0 to 1 over the first few hundred metres; without correcting it, near-range backscatter reads artificially low.
$$\text{glued\_oc}(R)=\frac{\text{glued\_ap}(R)}{\max\!\big(O(R),\,10^{-12}\big)},\qquad \text{NaN where } O(R) < O_{\min}.\tag{8}$$

Ranges where \(O(R)NaN rather than divided, so near-range noise is not amplified to meaningless values. \(O(R)\) itself is produced separately — analytically (Gaussian beam + Rice-CDF geometry) or from a file — and is out of scope here.

nrb_engine.py applies overlap_O_R (from overlap.py). Config: overlap_O_min=0.1.

9Range² correction + energy normalization → NRB

The physics problem. The lidar return falls off as \(1/R^2\) purely from the inverse-square spreading of light (the \(A/R^2\) term in Eq. L). Multiplying by \(R^2\) undoes it. Dividing by the laser pulse energy \(E\) makes profiles from different shots comparable — the "Normalized" in NRB.
$$\text{NRB}_{\text{phys}}(R) \;=\; \text{glued\_oc}(R)\cdot R^{2}\;\big/\;E, \qquad E=\text{energy\_mJ}\times10^{-3}\ \text{J}.\tag{9}$$

nrb_engine.py · nrb_final column. Config: energy_mj=25.0.

10Max normalization (0–1 profile)

The physics problem. For plotting and comparing profile shapes, a unit-max profile is convenient.
$$\text{NRB}(R) \;=\; \frac{\text{NRB}_{\text{phys}}(R)}{\max_R \text{NRB}_{\text{phys}}(R)}\tag{10}$$
Two columns, on purpose. The pipeline keeps both nrb_final (physical units, Eq. 9) and nrb (unit-max, Eq. 10). The depolarization step deliberately uses the physical nrb_final so the ∥ and ⊥ channels stay on a common scale and their ratio is meaningful.

nrb_engine.py · nrb_final vs nrb.

11Signal-to-noise ratio (SNR)

The physics problem. Photon counting obeys Poisson (shot) noise. The TR40 reports a per-bin error which, per the Licel manual (§9.3), is the standard error of the mean \(\sigma_\mu\) of the raw rate — not a raw standard deviation. Over \(N\) laser shots with per-shot counts \(x_i\), the transient recorder cannot expose each \(x_i\), so it accumulates the squared sums and stores \(\sigma_\mu\):
$$s=\frac{\text{sqd}}{\sqrt{N(N-1)}},\quad \text{sqd}=\sqrt{N\!\sum_i x_i^{2}-\Big(\sum_i x_i\Big)^{2}},\qquad \sigma_\mu=\frac{s}{\sqrt{N}}\tag{11a}$$

The signal we form the SNR against is the dead-time-corrected rate from Step 2, \(N_{\text{corr}}=N/(1-N\tau_d)\). That correction is non-linear, so the error must be propagated the same way — numerator and denominator have to describe the same quantity:

$$\sigma_{\text{corr}}=\sigma_\mu\left|\frac{dN_{\text{corr}}}{dN}\right|=\frac{\sigma_\mu}{(1-N\tau_d)^{2}}, \qquad \text{SNR}(R)=\frac{N_{\text{corr}}(R)-\text{BG}}{\sigma_{\text{corr}}(R)}\;\approx\;(1-N\tau_d)\,\text{SNR}_{\text{raw}}\tag{11b}$$
Scale-invariant for the later steps — so SNR of NRB = SNR of photon. Every operation after Step 5 (\(\times R^2\), \(\div O\), \(\div E\), \(\div\max\)) is linear: it multiplies signal and noise by the same factor, cancelling in the ratio. So the SNR computed here on the photon rate is the SNR of the final NRB, and can gate it directly in Step 12. The dead-time correction is the one non-linear step, which is exactly why its error is propagated in (11b): the net effect \(\text{SNR}_{\text{corr}}=(1-N\tau_d)\,\text{SNR}_{\text{raw}}\) is negligible in the far field (\(N\tau_d\to0\), where the trusted-range cutoff sits) and an honest reduction in the near field, where correcting near-saturated counts amplifies noise. The farthest bin with \(\text{SNR}\ge3\) is stored as trusted_range_snr3_m.

nrb_engine.py · SNR in build_single_profile(); keeps the raw \(\sigma_\mu\) as photon_stderr_MHz and the propagated \(\sigma_{\text{corr}}\) as photon_stderr_dt_MHz. The .dat error columns are Licel descriptors S2A (analog) / S2P (photon), i.e. the squared-sum-derived \(\sigma_\mu\) of (11a).

12SNR gating / trusted-range normalization optional

The physics problem. In daylight the far field is pure noise, and a max-normalization (Step 10) can lock onto a noise spike, corrupting the whole profile (a spurious \(R^2\)-amplified ramp). Gating restricts the profile to the contiguous range that is genuinely above noise.

Method. Smooth the SNR with a rolling median (window SNR_SMOOTH_BINS=15), then walk up from the SNR peak until the smoothed SNR drops below snr_min. Everything above that contiguous "trusted top" is masked, and the profile is re-normalized within \(\min(\text{top},\,\text{SNR\_NORM\_CAP\_M}=6000\ \text{m})\).

Why contiguous, not per-bin. A per-bin threshold lets ~25% of far-field noise bins randomly exceed 3σ, scattering fake points across the plot. A single contiguous cutoff from a smoothed SNR is stable.

nrb_engine.py · snr_trusted_top(), snr_gate_nrb(), _rolling_median(). Config: snr_gate (default False), snr_min=3.0.

Depolarization ratio (VDR)

The physics problem. A polarizing beam splitter sends the return to two PMTs: parallel (∥, co-pol) and perpendicular (⊥, cross-pol). Their ratio measures how much the target depolarizes the light — near 0 for spherical particles (fine aerosol), large for irregular ones (dust, ice). Because range², overlap, transmission and energy are common to both channels, they cancel in the ratio; only a fixed gain constant \(C\) remains, set by calibration in clean air.

Each channel is processed through the whole Part A chain (background- and afterpulse-corrected, before the overlap/\(R^2\) steps), then:

$$\delta^{*}(R)=\frac{P_{\perp}(R)}{P_{\parallel}(R)}\tag{D1}$$ $$C=\frac{\big\langle\delta^{*}\big\rangle_{\text{clean}}}{\delta_{\text{mol}}} \quad(\text{over } R\in[\,r_{\min},r_{\max}\,]\ \text{clean air})\tag{D2}$$ $$\delta_v(R)=\frac{\delta^{*}(R)}{C}\tag{D3}$$

with molecular depolarization \(\delta_{\text{mol}}=0.0044\) (narrowband, 532 nm). \(\delta^{*}\) is set NaN where the parallel signal is below a noise floor, and \(\delta_v\) is masked where the cross-pol SNR < snr_min. The calibration window default is 4500–5500 m. A single-channel mode also exists (process ∥ or ⊥ alone) for experiments where the two polarizations are measured on different days.

Terminology note. User-facing labels are ∥/⊥; internally (sheet names, columns, filenames) the channels stay co/cross. Also note this system's \(\delta = \text{cross}/\text{co}\) differs from the Mini-MPL convention \(\delta_{\text{MPL}} = \text{cross}/(\text{cross}+\text{co})\) — convert before validating against MPL.

depol_engine.py · compute_depolarization(), build_single_channel_for_file(). Constants DELTA_MOL_532_NARROW=0.0044, DELTA_MOL_532_BROAD=0.0144. Config: cal_rmin_m/cal_rmax_m, delta_mol, snr_min, snr_gate.

Part B — On-demand aerosol retrieval

Everything above produces the calibrated NRB (and depolarization). The steps below run on that NRB, when a quantitative aerosol product is wanted. They are not part of the routine per-file chain because each needs a physical choice from the operator (a clean reference range, a lidar ratio) or external inputs.

B1 · Rayleigh molecular model

The physics problem. To separate aerosol from air, the inversion needs the molecular backscatter and extinction the clean atmosphere would give on its own. These follow from air number density, which follows from a standard-atmosphere temperature/pressure profile.

Troposphere from the US Standard Atmosphere (ISO 2533), then ideal-gas number density and Rayleigh scattering:

$$T(h)=T_0-L\,h,\qquad P(h)=P_0\Big(\tfrac{T}{T_0}\Big)^{g/(L R_d)}\tag{B1a}$$ $$N=\frac{P}{k_B T},\qquad \beta_{\text{mol}}(R)=N\,\sigma_{\text{mol}},\qquad \alpha_{\text{mol}}(R)=\frac{8\pi}{3}\,\beta_{\text{mol}}(R)\tag{B1b}$$

with \(\sigma_{\text{mol},532}=5.45\times10^{-32}\ \text{m}^2/\text{sr}\), molecular lidar ratio \(S_m=8\pi/3\approx8.38\ \text{sr}\), and standard constants (\(T_0=288.15\) K, \(P_0=101325\) Pa, \(L=0.0065\) K/m, \(g=9.80665\), \(R_d=287.05\), \(k_B=1.380649\times10^{-23}\)).

fernald_engine.py · us_standard_atmosphere(), molecular_backscatter_532(), molecular_extinction(). (A scalar \(T,P\) shortcut exists for a single-layer approximation.)

B2 · Overlap function \(O(R)\) (analytical)

The physics problem. The \(O(R)\) that Step 8 divides out has to come from somewhere. For the biaxial geometry it can be modelled from first principles: a Gaussian laser beam imaged onto a circular field stop, offset by the laser–telescope baseline. The fraction of the beam image falling inside the field stop is a Rice cumulative distribution (Kumar & Rocadenbosch, 2013).
$$\sigma_{\text{beam}}=\sqrt{\sigma_0^{2}+(\sigma_\theta R)^{2}},\qquad \sigma_{\text{img}}=\frac{f}{R}\,\sigma_{\text{beam}}\tag{B2a}$$ $$\delta=\frac{\big|f\,(d_\perp-\text{tilt}\cdot R)\big|}{R},\qquad O(R)=\mathrm{Rice\text{-}CDF}\!\Big(x=\tfrac{r_{\text{fs}}}{\sigma_{\text{img}}},\ b=\tfrac{\delta}{\sigma_{\text{img}}}\Big)\tag{B2b}$$

clipped to \([0,1]\) and set to 0 below 1 mm range. Hardware (NARIT TR40): focal length \(f=2032\) mm, aperture \(D=203\) mm, baseline \(d_\perp=156\) mm, field-stop diameter 8 mm (\(r_{\text{fs}}=4\) mm). An empirical \(O(R)\) from a file can be used instead.

overlap.py · compute_analytical_overlap(), load_empirical_overlap(), get_overlap(); mode = disabled / analytical / file. Output feeds nrb_engine Step 8 as overlap_O_R.

B3 · Klett–Fernald inversion & aerosol products

The physics problem. The NRB still mixes backscatter with two-way transmission (the \(\exp[-2\!\int\alpha]\) term in Eq. L). The Fernald (1984) method separates aerosol from molecular backscatter by integrating the lidar equation backward from a clean reference range where the aerosol contribution is known (usually zero), using an assumed aerosol lidar ratio \(S_a\).

Input is the range-corrected signal \(S(R)=P(R)\,R^{2}\) (i.e. the NRB). With molecular lidar ratio \(S_m=8\pi/3\), the backward recursion from the reference bin \(i_{\text{ref}}\) is:

$$\beta_{\text{tot}}[i_{\text{ref}}]=\beta_{\text{aer,ref}}+\beta_{\text{mol}}[i_{\text{ref}}]\tag{B3a}$$ $$A=(S_a-S_m)\big(\beta_{\text{mol}}[i{+}1]+\beta_{\text{mol}}[i]\big)\Delta R,\qquad X_i=S[i]\,e^{A}\tag{B3b}$$ $$\beta_{\text{tot}}[i]=\frac{X_i}{\dfrac{X_{i+1}}{\beta_{\text{tot}}[i+1]}+S_a\big(X_i+X_{i+1}\big)\Delta R} \;\;\Rightarrow\;\;\beta_{\text{aer}}=\beta_{\text{tot}}-\beta_{\text{mol}}\tag{B3c}$$

Then the aerosol extinction, column optical depth, and (optionally) mass concentration:

$$\alpha_{\text{aer}}=S_a\,\beta_{\text{aer}},\qquad \text{AOD}=\int \alpha_{\text{aer}}\,dR,\qquad \text{mass}=\frac{\alpha_{\text{aer}}}{\sigma_{\text{ext}}}\times10^{6}\ [\mu g/m^{3}]\tag{B3d}$$
Coupling to depolarization. \(S_a\) can be a single value or a height-resolved \(S_a(R)\) derived from the depolarization ratio \(\delta_v(R)\) (dust has a higher lidar ratio than fine pollution), linking Part B back to the VDR. A Klett (1981) power-law inversion is also available as an alternative.

fernald_engine.py · fernald_inversion(), klett_inversion(), lidar_ratio_from_delta(), compute_mass_concentration(), compute_fernald_from_nrb_df(). Config: R_ref_m=5000, lidar_ratio_aer=50, method=fernald/klett.

B4 · PBL / aerosol layer-top (ALT) detection

The physics problem. The top of the aerosol layer (planetary boundary layer, or a lofted layer) shows up as a sharp drop in backscatter with height. It is found by locating the strongest falling edge in a smoothed NRB profile.

Two operators: an FFT low-pass to remove bin-scale noise, then a Haar wavelet covariance transform (HWCT) whose value is large where the profile steps down:

$$H(f)=\frac{1}{\sqrt{1+(f/f_c)^{2\,\text{order}}}},\qquad f_c\approx0.015\ \text{cyc/m}\ (\sim67\ \text{m})\tag{B4a}$$ $$W[i]=\big\langle\text{NRB}\big\rangle_{\text{right half}}-\big\langle\text{NRB}\big\rangle_{\text{left half}}\tag{B4b}$$

The layer top is the range of the most-negative \(W\) peak (strongest falling edge); a positive edge is used only if no falling edge exists. Cloud layers are screened separately (\(\text{OD}\approx0.5\ln(\text{NRB}_{\text{below}}/\text{NRB}_{\text{above}})\)) and the ALT can be temporally smoothed across a day.
